## First laboratory order

The treating clinician can open **Order laboratory test** from the current encounter, investigation summary or **Patient → Investigations**. The desktop side drawer/mobile bottom sheet shows patient identity and eligible encounter, searches the selected facility's available catalogue by name/code, displays the specimen requirement and records urgency/clinical indication. A final review shows the exact selected test/version, encounter and indication and requires an explicit review attestation before placing the request. No order is created during selection/review. Failed requests, stale catalogue selections and unsaved changes retain the authored information.

Orders pin the selected test ID and catalogue version and attribute the authenticated ordering clinician and time. The history refreshes after placement; **Review laboratory order** shows status, original indication, catalogue/specimen details and author. **Review cancellation → Confirm cancellation** records a reason, actor and time while retaining the original request. This action is allowed only while ordered, before any specimen/result exists. Processing/verification/release are separate workflows; placing an order does not imply collection, a result, patient notification or laboratory acknowledgment.

Migration 0043 adds facility test availability and order attribution/revision fields. One test per request is the deliberate first slice; repeat/add-on and override governance remain pending.

## Laboratory duty queue and specimen workflow

**Staff worklists → Laboratory** is available with `patient:read`, `lab:read` and `lab:worklist`. Duty access is through the facility's valid laboratory service orders, not an unrestricted patient care assignment. Staff can review necessary order, patient identity and specimen details; this capability does not grant access to the wider chart. Sidebar, workspace and general worklist search entry points expose the work area for laboratory-only accounts.

The queue includes all pending orders (ordered/collected/accessioned/resulted), with explicit stage filters and counts, prefix patient/test search or exact identifier, urgency then oldest-first ordering, complete matching counts/oldest age and cursor pagination (25 per page). Age is time since ordering; no unapproved overdue threshold is inferred. It refreshes every 20 seconds while active, pausing periodic refresh during specimen entry. Invalid/foreign/inconsistent order-patient-encounter links are excluded. Counts cover the complete matching queue, not only the displayed page.

**Review request → Review collection → Confirm collection** records the actual container, physical specimen identifier, actual time, authenticated collector and explicit patient/label confirmation. Collection requires `lab:collect`, active patient/encounter, current revision, ordered state and no prior specimen/result. It moves the request to awaiting receipt. Manual label entry is supported; barcode printing/scanning hardware validation is not implied.

**Review request → Review receipt → Confirm accession** requires `lab:accession`, the matching single collected specimen, an accession identifier, actual receipt time and explicit identity/suitability confirmation. It attributes the receiving staff and advances the request to accessioned/ready for testing. Already collected specimens may be received after encounter closure; new collection after closure is blocked. Retired patient identities, inconsistent/multiple legacy specimens and conflicting identifiers require governed reconciliation instead of an arbitrary choice. This slice accepts suitable specimens; rejection, conditional acceptance, recollection, additional aliquots and correction workflows remain pending.

Selection requires current membership, active credentials, acknowledgement permission and current patient care responsibility. A reason and explicit review/attestation are required. Scheduling does not grant care access or expose the finding to the backup before activation.

The in-API escalation worker checks durable scheduled rows every five seconds, including on startup. Concurrent workers serialize through the laboratory order/case locks; decisions, case revisions, metadata-only audit and outbox evidence commit together. Activation rechecks the recipient's credentials, membership and care access. A withdrawn/ineligible recipient produces a visible **blocked** record; the original case remains unresolved and laboratory staff must escalate directly or add another eligible clinician. Active covering clinicians receive the same persistent pending header/worklist access as the original clinician, subject to current care permissions. A missing facility MRN cannot be selected as a verified identifier. Arrival uses server time, remains attached to its booking history and does not clear a hold, advance acquisition or release capacity. Earlier/later appointment dates do not automatically establish or deny actual arrival; staff attest the attendance fact.

**Record no-show** requires separate `imaging:no-show`, an ended appointment, no arrival record and actual reviewed attendance/facility follow-up evidence. It is never automatic. The server uses the appointment end as a minimum gate; it does not invent a universal grace period or assume contact occurred. It releases the reservation and leaves the clinical request ordered for follow-up/rebooking. Concurrent arrival/no-show attempts lock the request and only one can succeed. Duplicate retries remain idempotent, later processing blocks attendance changes, and withdrawn permissions are checked on every request. Attendance notes/identifier values do not enter audit/outbox payloads. Correction of an incorrectly recorded attendance fact remains a governed follow-up workflow.

**Acquisition prerequisites** progressively displays live request/encounter eligibility, current reservation, verified arrival, current booked planning approval/template and resource availability. It is a read-only recorded-facts check with an independent refresh/error state and metadata-only audit. A newer hold/review, retired template, blocked resource or absent arrival changes the result. Satisfied prerequisites do not grant acquisition, procedure-day clinical safety clearance or contrast administration authority.

The user selected **Orthanc PACS**. A separate local compose service is running with localhost-only published ports, generated authentication, persistent storage, DICOMweb enabled and unknown modality storage/query/move disabled. The server-only gateway checks authenticated core/DICOMweb connectivity with bounded responses, timeouts, rejected redirects and sanitized errors; production plaintext endpoints are rejected. The browser sees only a sanitized connection indicator, never credentials or a general PACS proxy. This slice does not yet link Pulse requests to acquired studies, expose a viewer, author radiology reports or implement production modality worklists. See infra/README.md for the documented setup and primary Orthanc references.

Preparation rechecks the current order revision, active patient/open encounter, current appointment and arrival, latest booked planning approval/current mapping and resource availability. It creates an immutable work item with a server-generated accession and study UID, facility MRN/issuer and birth-date snapshot, checklist version/responses, actor/time and handover. ## Structured staff reporting and routine final sign-off

Migration 0058 adds structured, study-pinned report revision detail and attributable sign-off evidence, following IMG-001 sections 20–26. **Radiology → Review → Radiology report** supports technique, comparison, findings, impression and recommendations, finding priority and a revision reason. `imaging:report` is independent of acquisition and duty reads; `imaging:finalize` is a separate capability. The opt-in local preview seed grants both to demo.radiology/demo.admin. Role names alone grant nothing.

Each draft save appends a canonical img.report revision and immutable structured detail linked to the exact acquisition-verified study. The server supplies author attribution, serialises order writes, checks order/report identity and revision, deduplicates actor/key retries and retains prior drafts/reasons. Editing another revision cannot silently overwrite it. The operational `reported` stage is displayed as **Draft report** to avoid implying release. Legacy integration routes remain unavailable to staff sessions.

Routine final sign-off requires the latest complete draft (findings and impression), explicit diagnostic-image review reference, a sign-off note and attestation for patient/procedure/laterality and exact report revision. An authorised reporter can sign; this slice does not invent a universal independent-second-reader policy. Author and verifier are separately retained even when the same qualified user has both capabilities. Reporting/sign-off can occur after the encounter is discharged. Image review takes place on an approved diagnostic workstation; this report-text drawer is not a diagnostic viewer and does not claim to validate external image review automatically.

Sign-off evidence, canonical report final status, order final status, command receipt and metadata-only audit/outbox are committed atomically. Final reports and signature evidence cannot be overwritten through this workflow. The existing care/facility/domain-scoped patient chart continues to withhold drafts and exposes only the final latest text, with its actual sign-off timestamp. Final publication is not clinician acknowledgement. Recommendations remain narrative; saving one does not create a scheduled or completed follow-up action.

Urgent/critical drafts can be saved with their priority and evidence but final release is held until accountable communication/acknowledgement is implemented. Ordinary draft revision cannot reclassify an urgent/critical report to bypass that hold. The UI explains the hold and refers staff to their approved escalation process; there is no claim that saving or displaying a draft notifies the responsible team. Routine clinician result-review routing/notification and clinical acknowledgement remain pending too.

## Accountable urgent/critical imaging handoff

Migration 0059 connects urgent/critical report release to named clinical responsibility. **Radiology → Report → Start imaging handoff** requires explicit `imaging:communicate` plus patient:read/imaging:view/imaging:worklist, a complete current urgent/critical interpretation, a different active clinician with `imaging:acknowledge` and current patient care assignment, a staff-selected future deadline under facility policy and review/attestation. A deadline is mandatory and bounded to seven days technically; this is not a universal clinical response-time policy. No real patient/team assignment is seeded automatically.

Starting a handoff pins the exact report revision and advances the order revision. Subsequent report insertion/editing is blocked while that communication record exists, including after acknowledgement; governed correction/reconciliation remains separate work. Recipients cannot be casually replaced. Starting the record does not place a call, send a message or establish delivery. **Record imaging contact** records actual phone/in-person attempts, actor/time/note, reached/unreachable outcome and read-back. Unreachable attempts are retained and cannot satisfy acknowledgement. Contact times require an explicit time zone, cannot precede the handoff and cannot be more than one minute ahead of server time. Evidence is immutable.

The shared **Critical follow-up** page now includes an urgent/critical imaging section. Radiology communicators see their facility's cases; named recipients see only their own cases while current patient care access remains valid. The recipient sees the pinned interpretation with its explicit draft/final label, patient identity/study MRN and communication history. Only that named currently authorised clinician can acknowledge, after recorded reached/read-back evidence, with a note and attestation. Acknowledgement is not treatment and does not complete a recommendation. Concurrent retries are deduplicated, stale case versions rejected and revoked access rechecked.

Header and workspace follow-up counts combine authorised laboratory/imaging sources without requesting a domain the account cannot access. The imaging queue polls every 15 seconds, pages in groups of 25 and labels deadlines past due; it does not claim automatic timed backup routing. The latest 100 contact records are displayed in detail. Clinical notes/report narratives and recipient labels are absent from command receipts/audit/outbox metadata. Pinned content is available to the named recipient through this narrowly scoped handoff read even while ordinary patient-chart report publication remains withheld.

After explicit acknowledgement, a qualified reporter can finalise the same pinned urgent/critical report. The sign-off transaction and database guard require matching report ID/order revision plus acknowledged handoff; acknowledgement alone does not finalise anything. The authorised patient chart publishes final text and shows acknowledgement attribution separately. Routine report release is unaffected.
