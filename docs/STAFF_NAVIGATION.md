# Staff workspace navigation

Navigation uses the selected facility's live effective privileges, not login names or hard-coded role labels. A combined membership can expose multiple workflows. Sidebar links, worklist tabs, workspace search and direct worklist page access share `apps/web-clinical/lib/workspace-navigation.mjs`. API authorization remains authoritative for all reads and actions.

| Work area | Required privileges |
| --- | --- |
| Workspace, notifications, account security | Authenticated session; work areas require a selected facility |
| Patients | `patient:read` |
| Front desk | `encounter:read`, `appointment:read` |
| Nursing & vitals | `encounter:read`, `observation:write` |
| Consultations | `encounter:read`, `encounter:consult` |
| Laboratory | `lab:read`, `lab:worklist` |
| Critical follow-up | `lab:read` plus either `lab:critical:ack`, or `lab:worklist` with `lab:verify`/`lab:result` |

Account security and facility switching remain separate footer utilities. Facility switching appears only when multiple memberships are available. Sign out remains inside the profile menu with confirmation. Every worklist has a direct queue URL; tabs and the sidebar stay aligned. Unauthorized queue URLs show an unavailable state and never mount that queue. Search uses the same navigation catalogue. No privileges are added by this UI change.

Local role checks (2026-10-22): administrator sees all currently granted workflows; doctor sees Patients, Consultations and Critical follow-up; nurse sees Patients and Nursing & vitals; reception and records see Patients and Front desk; laboratory sees Patients, Laboratory and Critical follow-up. Pharmacy, radiology and cashier currently have only shared navigation because their department workspaces are not implemented/granted. The no-access account has no facility workspace. These are local fixtures, not a production role policy.

Imaging ordering is a patient-context action: **Patients → open an assigned patient → Investigations → Request imaging**. It requires `imaging:view`, `imaging:order` and `encounter:consult`, with active encounter/care responsibility enforced on the server. A radiology duty worklist is still pending and has no placeholder sidebar entry.

Authenticated HTTP checks against localhost:3001 compared server-rendered sidebar entries with effective capabilities for all nine facility-enabled demo accounts and verified all four direct queue URLs for each account. ## Daily workspace dashboard

The home workspace now provides a role-aware welcome/action area, live workload summaries, a six-entry queue preview, quick access and an updates/context column. It reads only permitted outpatient/laboratory queues and the user's notification feed; critical counts are requested only for eligible staff. Combined memberships expose selectable queues. Missing department workspaces show shared updates rather than fabricated metrics. No memberships or clinical records are created by the dashboard.

Outpatient counts describe the bounded active-visit list (up to 100, shown as 100+ at the limit), not daily arrivals or hospital totals. Laboratory totals use the server's pending-stage counts. Queue previews retain server ordering; Open leads to the full operational worklist. Counts and previews refresh every 30 seconds while visible and on focus; each source has its own error state. Failed reads display unavailable rather than zero and hide stale queue rows. Notifications are not critical acknowledgement. No trend, bed occupancy, finance or appointment KPI is invented.

Validated 2026-10-22: web types/lint and 17 regression checks pass. `node apps/web-clinical/tests/workspace-dashboard-smoke.mjs` (from repository root with the normal local app running and ignored demo credentials available) checks real Chrome doctor/nurse/laboratory panels, live load, blocked-request failure/retry and 390px mobile overflow. It creates no clinical records. Desktop/mobile screenshots are retained under ignored `tmp/clinical-notes-evidence/workspace-*.png`. Visual review refined the attention panel so amber appears only for pending critical follow-up. Sidebar layout is retained.

Radiology update (2026-10-22): facility-duty request queue and desktop/mobile review drawer are now delivered. Access requires `patient:read`, `imaging:view`, `imaging:worklist`; ordinary chart imaging reads do not grant it. Local demo.radiology/demo.admin are enabled by the opt-in imaging seed. Radiology now participates in sidebar/search, worklist tabs and live workspace cards. This supersedes the earlier statement that the radiology account has only shared navigation. Protocol/safety approval, scheduling/acquisition, reporting and PACS remain pending.

Protocol review access (2026-10-22): the request drawer exposes **Review protocol & screening** only to staff with explicit `imaging:protocol` in addition to radiology duty permissions, and an eligible operational/encounter state. Local demo.radiology/demo.admin receive this capability from the opt-in imaging seed. Backend checks revalidate current request version, patient/encounter state, processing and template availability. No clinical capability is inferred from a role name. Latest hold/approval-for-planning is distinct from the operational request stage.

Scheduling access (2026-10-22): `imaging:schedule` is required in addition to radiology duty reads. It permits booking a configured slot only after current protocol planning approval. It does not grant protocol decisions, equipment administration, capacity creation, rescheduling/cancellation or acquisition privileges. The preview seed grants it to demo.radiology/demo.admin. Missing approval/hold remains visible in the request drawer; the server also enforces approval and capacity at confirmation.

Appointment-change permissions (2026-10-22): `imaging:reschedule` permits moving an active unprocessed appointment under a current approved planning decision; `imaging:appointment:cancel` permits releasing it while leaving the clinical request open. Both require current radiology duty access. These do not grant initial-booking or clinical-request cancellation permissions. Availability reads accept initial-booking or rescheduling capability. Local demo.radiology/demo.admin receive the new capabilities from the explicit preview seed; no role label itself grants an action.

Attendance access (2026-10-22): `imaging:arrival` and `imaging:no-show` are separate duty actions. The former verifies actual attendance with two identifiers; the latter records reviewed absence after an appointment ends and only when no arrival exists. Neither grants protocol/scheduling/acquisition rights. Current radiology duty users can read live acquisition prerequisites and sanitized Orthanc connection health; neither is an acquisition authorization or a general PACS metadata proxy. The preview seed grants attendance actions to demo.radiology/demo.admin.

Acquisition access (2026-10-22): `imaging:acquire` plus patient:read/imaging:view/imaging:worklist exposes **Prepare acquisition** for an arrived scheduled request and **Verify received study** for a prepared request. Preparation requires a current configured procedure-day checklist; completion requires server-side Orthanc identity verification. No role label, planning approval or PACS connection indicator grants acquisition. Work-item/evidence reads remain available to duty readers. The explicit local preview seed grants the write capability to demo.radiology/demo.admin; refresh the workspace to reload effective privileges. Diagnostic viewing/report publication remain separate pending workflows.

Reporting access (2026-10-22): duty readers can inspect staff report history. `imaging:report` adds **Draft report / Revise draft** only for acquisition-verified acquired/reported requests. `imaging:finalize` independently adds **Review & finalise** for a complete routine draft, requiring image-review reference and explicit sign-off. Urgent/critical release remains held for accountable communication and cannot be bypassed by ordinary priority reclassification. Final text is published through existing patient-chart care/domain controls; drafts remain withheld. Demo.radiology/demo.admin receive preview report/sign-off capabilities from the explicit seed. Finalisation is neither notification delivery nor clinical acknowledgement.

Imaging handoff access (2026-10-22): `imaging:communicate` with patient:read/imaging:view/imaging:worklist adds recipient/deadline selection and actual contact/read-back recording. `imaging:acknowledge` with patient:read/imaging:view exposes shared **Critical follow-up**, but server reads/acknowledgement are restricted to the named recipient with current patient care access. Communicators have facility-duty visibility. The header and daily-workspace counts combine only the domains the account can use. Eligible recipients need live membership, active credentials, acknowledgement capability and current care assignment; the sender cannot assign the case to themselves. The opt-in preview grants communication to demo.radiology/demo.admin, acknowledgement to demo.doctor/demo.admin. Imaging acknowledgement unlocks qualified sign-off of the pinned report; it does not finalise the report, record treatment or imply delivery through an external channel.
